# 栞チームで有料noteを作るプロンプト

栞チーム（`.claude/agents/` の4人）に、有料noteを一本作らせるためのプロンプトです。
Claude Code に貼り付けて使います。`{ }` の中を書き換えてください。

---

## 1. 通しで作る（基本）

```
栞チームで、note の有料記事を一本作ってください。

■ テーマ：{例：純喫茶で一人、休日の午前を過ごすための手引き}
■ 読者：{例：休日にも予定を入れてしまい、何もしない時間が落ち着かない人}
■ 対応する症状パターン：{例：〔1〕休み方を忘れた}（symptom-patterns.md 第2章）
■ 価格：{500}円
■ 字数の目安：{6,000〜8,000}字
■ 保存先：note/{ファイル名}.md（本文）、note/{ファイル名}-hanbai.md（販売設計）

進め方：
1. リサーチ担当（shiori-researcher）：競合の note、読者の悩み、本文に入れる事実の確認。出典つき。
   確認できなかったことは「未確認」と書かせる。
2. 執筆担当（shiori-writer）：リサーチをもとに初稿。
   無料部分＝情景の導入／向いている人・向いていない人／目次／本文の見本を一項目。
   有料部分＝障壁の解除 → 実用の手順 → 状態別・時間別の使い方 → スクショ用の付録。
3. 編集担当（shiori-editor）：価値・禁則・事実の三点で校閲。字数はスクリプトで数える。
4. 執筆担当が指摘を反映する。
5. 販売担当（shiori-sales）：タイトル5案、価格と有料ラインの根拠、見出し画像の文言、
   Instagram 告知（リールのテロップ6枚＋キャプション）、ハッシュタグ、公開前チェックリスト。

守ること：
- symptom-patterns.md の禁則（評価語・命令形の勧誘・二人称の勧誘・店名の推奨）を本文と告知の両方で守る
- 実在の店名を出さない
- 締めは一人称の報告で終える
- 本文に書いた字数と実際の字数を合わせる
- 各段階が終わるたびにコミットして push する

最後に、各担当が何を変えたかと、未確認のまま残ったことを短く報告してください。
```

---

## 2. 一人だけ動かす

### リサーチだけ

```
リサーチ担当（shiori-researcher）として、{テーマ}の有料 note を作る前の調査をしてください。
競合 note の価格・タイトルの型・構成、読者の悩み（symptom-patterns.md の障壁番号と対応させる）、
本文で使う事実 {確認したい事実} の裏づけ。出典URLつき、未確認は未確認と書く。
```

### 書き直しだけ

```
執筆担当（shiori-writer）として、note/{ファイル名}.md の {章} を書き直してください。
理由：{例：実用寄りで、栞の声が薄い}
文体は一人称の報告、情報は情景に変換（symptom-patterns.md 第5章）。
終わったら字数と、禁則に触れていないかを報告。
```

### 校閲だけ

```
編集担当（shiori-editor）として、note/{ファイル名}.md を校閲してください。
原稿は書き換えず、行番号つきの指摘と修正案を返す。
観点：500円の価値があるか／禁則と文体／事実の言い過ぎ／字数表記。
```

### 告知だけ

```
販売担当（shiori-sales）として、note/{ファイル名}.md の Instagram 告知を作ってください。
リールのテロップ6枚（一枚目は時間×場所×動作の状況起点フック、症状パターン〔{番号}〕）、
キャプション（最後は一人称の報告）、ハッシュタグは最初のコメント用に分ける。
禁則：おすすめ／美味しい／映え／今すぐ／ぜひ／保存して／行ってみて／あなたも。
```

## 3. 次のテーマ候補

症状パターンごとに一本ずつ作れます。第一作（`note/hitori-junkissa-tebiki.md`）は障壁の解除が中心なので、次は状態から入るテーマが続けやすいです。

| 症状パターン | テーマ案 |
|---|---|
| 〔1〕休み方を忘れた | 何もしない休日の午前を、純喫茶で過ごすための手引き |
| 〔4〕頭が仕事から離れない | 仕事帰りの三十分で、頭を置いてくる喫茶店の使い方 |
| 〔6〕一人きりも寂しい | 誰とも話さずに、人の気配の中にいるための夜の喫茶店 |
| 〔7〕時間が余った | 約束までの四十分を、純喫茶で過ごす小さな手引き |
